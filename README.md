# Bluetooth-диагностика для Windows 11

Приложение на C# и WinUI 3 проверяет адаптер, драйвер и службы Windows, ищет Bluetooth Classic и BLE, выполняет сопряжение и проверяет, появился ли аудиовыход. Готовая сборка Windows x64 поставляется с .NET и Windows App Runtime. Распакуйте архив целиком и запустите `RnxBluetoothDiagnost.exe`. Для обычного запуска права администратора не требуются.

## Проверка на двух ноутбуках

1. На ноутбуке, к которому хотите подключить гарнитуру, выберите её модель в приложении. Временно отключите Bluetooth на другом ноутбуке и на телефоне, если гарнитура подключается к нему автоматически.
2. Включите режим сопряжения по подсказке и нажмите **Начать поиск**. Для G435 удерживайте **Power + Mute** не менее трёх секунд до мигания синего индикатора. Если гарнитура в режиме LIGHTSPEED, сначала переключите её в Bluetooth удержанием **Mute**. У W820NB Plus способ зависит от ревизии. [Сопряжение G435](https://support.logi.com/hc/en-us/articles/4409383783959-How-to-connect-your-G435-using-Bluetooth) · [Переключение режима G435](https://support.logi.com/hc/en-150/articles/4409383834519-How-to-switch-the-connection-mode-between-Lightspeed-and-Bluetooth-on-G435) · [Ранняя ревизия W820NB Plus](https://usa-oss.edifier.com/Uploads/images/2023/03/14/2023031413565616787734169944.pdf) · [Новая ревизия W820NB Plus](https://new-edifier-us-oss.edifier.com/files/20250703/3739da179d5aa5fb3f8039484773b4b1.pdf)
3. Выберите запись гарнитуры. Для G435 и W820NB Plus начните с **Classic**, если Windows показывает две записи. Нажмите **Сопрячь** и подтвердите запрос Windows, если он появится. После сопряжения нажмите **Проверить аудиовыход**. Если выход доступен, его можно выбрать в настройках звука Windows.
4. Если гарнитура пропала из поиска, повторите опыт на втором ноутбуке: отключите Bluetooth на первом, заново включите режим сопряжения и запустите поиск. При необходимости скопируйте отчёты обоих ноутбуков из **Журнала диагностики**.

## Как читать результаты

- **Запись Windows** или **сопряжено** без свежего отклика означает, что Windows знает устройство. Для нового подключения ещё нужно, чтобы гарнитура ответила на поиск.
- **Classic inquiry** показывает, обновила ли Windows время обнаружения во время активного поиска. Запрос обычно занимает около 10 секунд. Если остановить поиск во время запроса, приложение дождётся его завершения.
- **BLE, дБм** — сила последнего принятого пакета. Подойдите ближе и сравните несколько измерений. Помехи и положение гарнитуры влияют на показания. Пакеты BLE могут приходить с меняющихся адресов и сами по себе не подтверждают доступность аудио. [Документация Microsoft по BLE](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/bluetooth-low-energy-overview)
- **Забыть** удаляет сопряжение выбранного устройства после подтверждения. Если Windows возвращает ошибку, её код виден в журнале. Скопированный отчёт содержит адреса обнаруженных устройств.

## Сборка

Из PowerShell в каталоге проекта, с установленным .NET 10 SDK:

```powershell
dotnet build -c Release
dotnet publish -c Release -r win-x64 -o .\artifacts\BluetoothDiagnost-win-x64
```

На Windows 11 ARM64 для нативного доступа к радиомодулю используйте `-p:Platform=ARM64 -r win-arm64`. [Требование Microsoft к архитектуре](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothadapter.getradioasync)
